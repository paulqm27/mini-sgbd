# Etapa 14-15-16: Plan de trabajo

Este documento describe los pasos a seguir para implementar las funcionalidades de las semanas 14, 15 y 16 sobre la base del proyecto actual `mini-sgbd`.

---

## Semana 14 — Implementación del Modelo de Iterador (Volcano)

Objetivo: Definir e implementar la infraestructura de iteradores (Volcano) y los operadores básicos: `Scan`, `Select` y `Project`.

Pasos:
- Diseñar la interfaz base `Iterator` (métodos: `open()`, `next()`, `close()`, `reset()` opcional).
- Definir estructuras de tupla/registro y esquema mínimo necesario para operadores.
- Implementar `Scan` sobre las abstracciones de `Storage`/`Page` existentes.
- Implementar `Select` como operador que envuelve otro `Iterator` y aplica predicados.
- Implementar `Project` para transformar/seleccionar columnas desde el `next()` de su child.
- Integrar manejo de errores y recursos con el `Buffer Manager` (pinned pages, release).
- Añadir ejemplos y pequeños demo-tests que encadenen `Scan -> Select -> Project`.

Entregables semana 14:
- Implementación de interfaces y operadores en `src/index/` o `src/execution/`.
- Demo simple y pruebas unitarias básicas.

---

## Semana 15 — Algoritmo de Join y uso del índice B+ Tree

Objetivo: Implementar al menos un algoritmo de `Join` (p.ej. Nested Loop Join) y aprovechar el índice B+ Tree para optimizar consultas.

Pasos:
- Implementar `NestedLoopJoin` como `Iterator` que toma dos child `Iterator` (outer, inner).
- Diseñar API para joins (join condition/predicado, materialización parcial opcional).
- Medir y documentar costos básicos (número de accesos a páginas) para Nested Loop.
- Integrar soporte para usar índice B+ Tree dentro de `Scan` o crear un `IndexScan` operator que use el índice existente.
- Modificar/añadir hooks para que el planificador/consulta elija `IndexScan` cuando exista índice y la selección esté sobre la columna indexada.
- Validar corrección mediante tests de join y consultas indexadas.

Entregables semana 15:
- `NestedLoopJoin` y `IndexScan` funcionales.
- Ejemplos comparativos (secuencial vs índice).

---

## Semana 16 — Pruebas, mediciones y reporte final

Objetivo: Realizar pruebas exhaustivas, medir rendimiento y tasa de aciertos del `Buffer Manager`, y preparar el informe técnico final.

Pasos:
- Diseñar un conjunto de pruebas unitarias y de integración que cubran Scan/Select/Project/Join e índice.
- Crear datasets de prueba (pequeño, medio, grande) y scripts para cargar datos.
- Implementar benchmarks medibles: latencia por consulta, throughput, número de page faults, accesos a disco simulados.
- Instrumentar el `Buffer Manager` para recolectar métricas: accesos, hits, misses, evictions, hit rate.
- Ejecutar experimentos variando parámetros: tamaño del buffer pool, tamaño de página, presencia/ausencia de índices.
- Recolectar resultados y generar gráficas/tablas (CSV) para el informe.
- Redactar el informe técnico final con: objetivos, diseño, resultados (tablas/figuras), análisis de hit rate y recomendaciones.

Entregables semana 16:
- Suite de pruebas y scripts de benchmark en `tests/benchmarks/`.
- CSV/PNG con resultados de medición.
- Informe técnico `informe_final.pdf` o `informe_final.md` con conclusiones.

---

## Riesgos y notas técnicas
- Asegurarse de no romper APIs públicas del `Storage` y `Buffer Manager`.
- Priorizar la corrección funcional antes de optimizaciones prematuras.
- Mantener pruebas pequeñas y reproducibles para facilitar el debugging.

## Cronograma y estimaciones (alto nivel)
- Semana 14: 3–5 días (diseño + implementación operadores + pruebas básicas).
- Semana 15: 3–5 días (join + index scan + integración).
- Semana 16: 4–7 días (pruebas exhaustivas, benchmarking, informe).
